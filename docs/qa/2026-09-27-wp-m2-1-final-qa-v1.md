## 3. Final Runtime Architecture (as-built)

```
RP findings (authoritative)
  → Coverage Check [WI-2, flag: COVERAGE] → auto-register INCOMPLETE /
    invalidate on semantic change / gone-drift   → telemetry
  → Metadata Catalog (candidate_metadata) + Concept Registry
      [WI-1 storage; WI-3 seed: 6 concepts, F5/F6/F8 COMPLETE,
       F1/F2/F3/F4/F7 INCOMPLETE]
Conversation turn:
  → Stage-1 ContextResolver (shared with Agent Loop — same class,
    same semantics)
  → AMBIGUOUS → frozen refinement PROPOSAL
  → WI-5 SafeSelectGate: eligibility (COMPLETE only) → WI-4
    SupportEvaluator (normalization → Registry conformance → grounding
    → deterministic CORE mapping → set predicate, UNKNOWN first-class)
    → uniqueness → target identity → confidence
  → ADMIT → resolved/inferred focus | REJECT → bounded clarification
    [WI-6 ledger: clarified → terminal on identical repeat |
     resolved_by_designation on explicit focus]
Agent Loop:
  → same Stage-1 resolver → AMBIGUOUS terminates BLOCKED/
    clarification_needed at the user-interaction boundary; boundary is
    recorded in the SHARED clarify ledger; the loop never selects and
    is never resumed in place — resumption is a conversation-path
    state transition (explicit designation / rephrased request).
Telemetry [WI-7]: observational events at every decision point;
  never a decision input.
```

## 5. Agent-Loop Integration Closure (the WI-5/WI-6 open gap)

**Resolved as "no bypass path exists, by construction", with structural
and behavioral proof:**

1. `AgentLoopRunner.__init__` accepts no `refinement_resolver` or
   `metadata_admissibility` — the loop cannot invoke the frozen
   refinement or the gate (structural test: signature inspection +
   source scan for `refine_target`/`SafeSelectGate` — both absent).
2. The loop's context resolution uses the SAME `ContextResolver` class
   and semantics as the turn path (structural test: isinstance check) —
   no second, weaker candidate-selection policy.
3. Behavioral proof: an AMBIGUOUS loop goal terminates
   BLOCKED/`clarification_needed` with NO focus set and no selection
   (flags fully ON in the test) — autonomous selection is unreachable.
4. The loop's clarification boundary is recorded in the SHARED clarify
   ledger (`agent_loop_blocked` reason), and resumption happens through
   the conversation path (explicit designation → focus; rephrased
   request → fresh evaluation) — verified end-to-end (WI-6 E2E-6).
5. `_findings_strict` remains the loop's RP boundary (strict errors,
   no coverage reconcile) — documented residual: reconciliation runs on
   the conversation path; the loop path surfaces governed statuses via
   the shared catalog at its clarification boundary. No bypass of
   Safe-Select exists because the loop has no Safe-Select seam.

## 13. Safety Invariants (all verified)

1. UNKNOWN never treated as FALSE — predicate tests + gate propagation.
2. INCOMPLETE/UNVERIFIED/DEPRECATED never Safe-Select-eligible — gate
   eligibility short-circuit (matrix cases 2–4).
3. User designation never changes metadata verification — DB-verified.
4. LLM output never directly controls selection — RoutingFakeLLM
   adversarial tests + structural no-LLM-in-gate.
5. Telemetry never controls runtime decisions — emissions are
   observational; failure-injection E2E-9.
6. New candidates enter lifecycle without candidate-specific code —
   data-driven reconcile (F12 scenarios).
7. Repeated unresolved clarification is bounded — terminal ×3 stable.
8. Explicit focus and autonomous Safe-Select remain separate paths.
9. Agent loop has no second candidate-selection policy — structural +
   behavioral (BLOCKED, never selects).
10. Flags OFF preserve pre-WP-M2-1 behavior — equivalence verified.

## 14. Known Limitations

1. Agent-loop Safe-Select: the loop has no refinement seam, so
   autonomous Safe-Select is turn-path-only. When the loop adopts
   refinement, the same gate object must be wired (single integration
   point, already provider-based).
2. `_findings_strict` does not run Coverage reconcile (conversation
   path does). The loop surfaces governed statuses via the shared
   catalog at its clarification boundary; reconciliation on the loop
   path remains a documented follow-up.
3. Concept Registry + candidate metadata for the live universe are
   seeded/authored fixture-and-baseline data (U00010); authoring for
   new domains is a governance activity outside the runtime.
4. LLM endpoint fragility (empty/invalid outputs, intermittent
   unavailability) degrades journeys safely (CLARIFY/fallback) but
   adds variance to user experience.
