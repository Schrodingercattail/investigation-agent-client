## 6. 故障分类与判定标准

本文档统一采用以下五类故障分类(A–E)。后续任何引用本调查的记录都应使用该分类。

### A. Provider 连接失败

- **定义**:请求未能正常建立,或 Provider 连接失败。
- **Agent 侧表现**:记录 `LLM_UNAVAILABLE`。
- **本轮出现情况**:0(未出现)。
- **历史案例**:历史 D 场景(见第 9.1 节)。
- **F3 适用性**:**不适用**。
- **业务解释**:这一类故障下根本没有获得有效的模型输出,规划链路从源头中断。

### B. Provider 流式传输中断

- **定义**:请求已进入流式传输,但传输过程中连接/协议中断。
- **典型特征**:如 `httpx.RemoteProtocolError`(Provider 侧 peer closed)。
- **本轮出现情况**:0(未出现)。
- **历史案例**:TASK-8b67ad17e3ec(见第 9.2 节)。
- **F3 适用性**:**不适用**(该类故障没有形成可供 F3 接管的 `LLM_OUTPUT_INVALID` 规划失败形状)。
- **业务解释**:这一类故障是传输通道断开,不是"模型返回了格式错误的完整文本",也不是 Agent 解析程序缺陷。

### C. 模型输出格式/结构异常

- **定义**:Provider 正常返回内容(HTTP 200、流式传输完整),但返回内容不符合 Agent 预期的输出契约(格式/结构)。
- **Agent 侧表现**:既有输出契约校验判定不合格,错误码 `LLM_OUTPUT_INVALID`。
- **本轮出现情况**:1 次(Planner 返回约 45 字符短文本,见第 7 节)。
- **F3 适用性**:**在满足 withdrawal_records 专用门控条件时,F3 可以兜底**(见第 8 节)。
- **业务解释**:这一类故障中模型确实给出了内容,只是内容不合格;因此存在"用确定性规划替代该次规划"的兜底空间。

### D. Agent 流式读取、内容提取或解析程序故障

- **定义**:Agent 自身的流式拼接、thinking/text 提取、结束标记处理或 schema 解析代码出现缺陷。
- **本轮出现情况**:**未发现此类故障证据**。
- **F3 适用性**:不适用(F3 不是解析程序缺陷的修复机制)。
- **证据纪律**:本轮"未发现证据"**不得**写成"绝对不存在"。

### E. 业务工具执行失败

- **定义**:LLM 已经完成规划,但后续业务工具执行失败。
- **归属**:工具/业务执行层问题,**不等于** Provider 或模型调用失败。
- **F3 适用性**:不适用。**F3 不应被描述为业务工具执行失败的通用修复机制**。
- **业务解释**:该类故障发生在规划成功之后,与 LLM 调用可靠性属于不同层面的问题。

### 判定标准要点

1. **`LLM_OUTPUT_INVALID` 与 `LLM_UNAVAILABLE` 不得混为一谈**:前者是"Provider 正常返回了内容,但内容不符合契约"(类型 C);后者是"Provider 连接失败,根本没有有效输出"(类型 A)。
2. **流式传输中断不得归类为 Agent 解析程序故障**(类型 B ≠ 类型 D):前者是 Provider 与 Agent 之间通道断开,后者是 Agent 自身代码缺陷,判定必须有对应证据。
3. **HTTP 200 不得等同于业务任务成功**(见第 3.3 节)。
4. 对没有证据的事项,一律表述为"未发现证据"或"NOT PROVEN",不得自行补齐结论。

## 7. 本轮 Planner 输出异常案例

### 7.1 现象

本轮 7 次 Planner 调用中,有 1 次返回了**约 45 字符的短文本**,不符合 Planner 输出契约对计划结构的要求。

### 7.2 逐层判定

| 判定层 | 结论 | 依据 |
| --- | --- | --- |
| Provider 层 | 正常返回,HTTP 200 | 排除故障类型 A(Provider 连接失败) |
| Streaming 层 | 没有证据表明发生了流式传输中断 | 排除故障类型 B |
| Agent 解析层 | 没有证据表明是 Agent 的流式拼接、thinking/text 提取或 schema 解析程序故障 | 排除故障类型 D(注意:是"没有证据",非"绝对排除") |
| 内容契约层 | Agent 按既有输出契约校验,判定输出不符合预期,错误码 `LLM_OUTPUT_INVALID` | **判定为故障类型 C** |

### 7.3 定性与处置

- **定性**:该次异常属于"**模型返回内容不符合 Agent 预期输出格式/结构**"。它**不是** Provider 连接失败,**不是**流式传输中断,**也不是** Agent 解析程序故障。
- **处置**:该次异常触发了 **F3 deterministic withdrawal-records fallback**;F3 确定性构造的计划被采纳并执行,**完成交付**(详见第 8 节)。
- **对统计的影响**:Planner 本轮 7 次调用按 6 次成功、1 次异常计,成功率约 85.7%(仅代表本轮)。

## 8. F3 确定性兜底机制

### 8.1 业务场景

F3 是针对 **U00043 账号级提现记录检索场景**的**确定性规划兜底**。

业务背景:

- 用户要求获取**账号级提现记录**;
- 该类记录流可能**跨越多个 finding**,因此不能因为 Planner 输出异常,就直接丢失用户明确的记录交付意图;
- **正常情况下 Planner 输出有效时,仍走原有 Planner 路径**;
- **只有 Planner 规划失败且错误码为 `LLM_OUTPUT_INVALID` 时**,才尝试 F3 fallback。

### 8.2 触发条件

F3 仅在以下条件**全部满足**时触发(本轮 5 项全部满足):

1. 存在**已接受的 Goal Contract**;
2. 输出要求**严格属于 withdrawal_records**;
3. 存在**对应的 withdrawal 记录流和工具绑定**;
4. 确定性构造的计划**能够通过输出覆盖校验**;
5. 最终构造并采纳 **inspect_withdrawals 计划**,进入原有执行和交付链。

### 8.3 本轮执行结果

| 项目 | 结果 | 业务解释 |
| --- | --- | --- |
| 触发次数 | 1 次 | 对应本轮唯一一次 Planner `LLM_OUTPUT_INVALID` |
| 触发方式 | 真实运行时触发 | 不是测试模拟,是本轮实际运行中发生 |
| fallback 计划 | 被采纳 | 确定性构造的 inspect_withdrawals 计划通过了输出覆盖校验并被采纳 |
| 执行与交付 | 执行并完成交付 | 用户明确的记录交付意图未因 Planner 异常而丢失 |
| 本轮验证结论 | **PASS** | F3 的有效性通过本轮真实运行时的触发、采纳、执行、交付全链路得到验证 |

### 8.4 不适用范围

F3 **不适用于**以下情形:

1. **不适用于**任意工具或任意业务主题的通用 Planner 故障;
2. **不适用于**混合了其他 evidence requirements 的契约;
3. **不适用于**缺少有效 Goal Contract、缺少 withdrawal_records 需求、缺少对应工具绑定,或无法证明覆盖完整性的情况;
4. **不适用于** Provider 连接失败(类型 A)、流式传输中断(类型 B)等其他故障类型;
5. **不适用于**显式 finding 级目标的任意规划问题;
6. **不应将 F3 描述为**通用 LLM 重试机制或通用 Agent fallback。

### 8.5 特别说明

F3 解决的是**特定业务场景(U00043 账号级提现记录检索)下 Planner 输出结构异常后的确定性规划兜底**。它**不是修复 Provider**,也**不是修复模型本身**。对故障类型 A、B、D、E,F3 均不构成修复或兜底手段。

**业务解释**:该案例说明 GU 锚定成功不等于整链成功——Provider 连接失败使后续规划根本没有发生,F2 交付链在该次运行中未被证明。

### 9.2 历史案例二:流式传输中断(TASK-8b67ad17e3ec)

## 12. 术语表

| 术语 | 解释 |
| --- | --- |
| **LLM**(Large Language Model) | 大语言模型,本轮调查中指 Agent 运行时所依赖的语言模型服务。Planner 输出异常(类型 C)发生在模型返回内容层面。 |
| **GU**(Goal Understanding) | 目标理解阶段。用户请求进入 Agent 后,由该阶段理解用户目标并完成主体锚定(如 finding、账号)。本轮 GU 7/7 成功;历史 D 场景中 GU 锚定 F2 正确,但后续 Provider 连接失败使整链未完成。 |
| **Planner** | 规划阶段,负责将用户目标映射为结构化计划。本轮 7 次调用中 6 次成功,1 次输出不符合契约,触发 `LLM_OUTPUT_INVALID`。 |
| **Provider** | 外部 LLM 服务提供方。本轮经由 z.ai `/v1/messages` 端点访问。Provider 连接失败为类型 A 故障。 |
| **HTTP** | 超文本传输协议,LLM 调用的底层请求-响应协议。HTTP 记录数是传输层口径,包含 SDK 内部重试,不等同于逻辑 LLM 调用次数。 |
| **HTTP 200** | HTTP 成功响应状态码。它只表示对应那次请求获得了成功响应,**不等于业务任务成功**,也不代表返回内容符合契约。 |
| **Streaming**(流式传输) | Provider 向 Agent 分段传输响应内容的传输方式。传输中途连接/协议中断即类型 B 故障(如 `httpx.RemoteProtocolError`)。 |
| **SDK retry**(SDK 内部重试) | LLM 客户端 SDK 在内部自动发起的补充请求。这类请求同样计入 HTTP 请求记录数,因此 HTTP 记录数大于独立逻辑调用数。 |
| **LLM_OUTPUT_INVALID** | 错误码:Provider 正常返回了内容,但内容不符合 Agent 预期的输出格式/结构(类型 C 故障)。与 `LLM_UNAVAILABLE` 含义不同,不得混用。 |
| **LLM_UNAVAILABLE** | 错误码:Provider 连接失败、没有获得有效模型输出(类型 A 故障)。历史 D 场景中记录了该错误码。 |
| **deterministic fallback**(确定性兜底) | 不依赖 LLM、按预定义确定性规则构造替代方案的处理机制。本轮共发生 1 次,即 F3。 |
| **F3** | 针对 U00043 账号级提现记录检索场景的确定性规划兜底:仅在 Planner 规划失败且错误码为 `LLM_OUTPUT_INVALID`、且满足 withdrawal_records 专用门控全部条件时,确定性构造并采纳 inspect_withdrawals 计划。不是通用 LLM 重试机制,也不是通用 Agent fallback。 |
| **E2E**(End-to-End) | 端到端验证:从真实入口出发、跨实际集成边界(如 UI → API → 服务 → 运行时 → 依赖)验证完整行为链。F3 本轮的真实运行时验证属于运行中的实际链路验证,其结论(PASS)限于 withdrawal_records 场景。 |
